# Juvia Full-Stack Integration Gap Report

Generated by comparing `backend-inventory.md` and `frontend-inventory.md`.

---

## Executive Summary

The Juvia backend exposes **~110 REST/WebSocket endpoints** plus many settings/task/audit endpoints. The frontend consumes only **~55 distinct endpoints**, and several of those are used incorrectly (wrong method, wrong payload, or wrong response field). Many backend capabilities have no frontend equivalent, and several frontend screens are static placeholders that do not call any backend.

Top integration risks:
1. **Settings, Terminal, Session Recordings, and User Management** are almost completely disconnected.
2. **File upload is broken** for binary content and **file extraction** is a backend stub.
3. **WebSocket task progress** is subscribed but never published.
4. **Per-site RBAC** exists in the schema but is enforced nowhere.
5. **No CSRF validation, rate limiting, or password complexity** controls are wired end-to-end.

## Gap Details

### Gap 001
- **Gap ID:** GAP-001
- **Severity:** Critical
- **Module:** Settings
- **Problem:** The entire Settings page (`/settings`) is static HTML with no backend integration.
- **Root Cause:** Frontend `Settings.tsx` uses `defaultValue` on inputs and static buttons; no `api` calls made.
- **Evidence:** `frontend-inventory.md` line 191; `Settings.tsx` has no `api` import usage for mutations.
- **Affected Files:** `web/src/pages/Settings/Settings.tsx`, backend `internal/api/settings.go`
- **Required Work:** Wire GET `/settings` to populate tabs, PUT `/settings` on save, `/settings/export`, `/settings/import`, `/updates/*`, `/users/*` integration for Users tab.
- **Dependencies:** Requires backend settings endpoints to be functional.
- **Risk:** Users cannot configure server; panel appears to work but changes are lost.

### Gap 002
- **Gap ID:** GAP-002
- **Severity:** Critical
- **Module:** Terminal
- **Problem:** Frontend creates terminal sessions but cannot connect to them.
- **Root Cause:** `Terminal.tsx:157` "Connect" button has no `onClick`; no WebSocket terminal component exists.
- **Evidence:** `frontend-inventory.md` line 193.
- **Affected Files:** `web/src/pages/Terminal/Terminal.tsx`, backend `internal/api/terminal.go`, `internal/agent/terminal/record.go`
- **Required Work:** Build a terminal emulator (xterm.js) connected to a WebSocket or bidirectional API; backend needs `/ws/v1/terminal/:sessionId` route and real PTY.
- **Dependencies:** Agent terminal PTY implementation.
- **Risk:** Core "terminal access" feature is non-functional.

## Recommendations

1. **Fix critical broken features first:** Settings, Terminal, file upload/extraction, DB export, DB users, DNS, apps, backups, alerts, catch-all, metrics history.
2. **Build missing CRUD pages:** Users, audit log, recordings, first-run wizard, per-site logs.
3. **Standardize data fetching:** Migrate from hand-rolled `useEffect` to React Query for caching, loading, error, and pagination.
4. **Add end-to-end security:** CSRF validation, rate limiting, role-based guards, and per-site filtering.
5. **Wire backend events:** Publish task progress so long-running operations show real-time status.
6. **Add error boundaries, 404 route, and global toast/error patterns.**
7. **Keep navigation in sync** by generating sidebar/command palette from a single route/feature config.
